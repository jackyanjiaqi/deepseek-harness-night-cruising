# 文档服务

每个会话拥有独立的文档服务。它完整复刻 `cmd_tools/doc-server`：同一套 `lib/`、`public/`、Markdown 渲染、目录树、预渲染、Mermaid、目录知识图谱、`/raw`、`/api/document`、`/graph` 等能力，只是根目录、端口和实例改为按会话管理。

## 打开方式

- **会话视图标签**：会话标题右侧的 View 标签中出现「文档服务」。标签内嵌该会话自己的文档服务页面；未启动时可直接以工作空间根目录启动或选择目录。
- **侧边栏工作区文件右键**：
  - 目录 → 「启动目录」或「切换目录」。启动/切换后自动打开该会话的「文档服务」标签。
  - 文件 → 「定位文件」。文档服务未启动时先以会话工作空间根目录启动，再定位文件；已启动时定位到当前根目录内的文件。文件不在当前根目录内会明确报错，可先切换目录。定位后自动切到「文档服务」标签。
- **agent 工具 `doc_server`**：让 agent 输出文档服务文件链接。工具结果在对话中渲染成「在文档服务中打开」的卡片，并返回可直接引用的 URL。示例：
  - `doc_server({ action: "open", file: "docs/guide.md" })`
  - `doc_server({ action: "switch", directory: "docs" })`
  - `doc_server({ action: "list" })`
- **设置 → 文档服务**：列出所有已启动服务，显示会话标题、地址、端口、根目录、最后定位文件；「跳转」会打开对应会话并切到它的「文档服务」标签，展示最后定位的位置。

## 行为

- 每个会话一个 HTTP 服务，端口由系统分配，绑定 `127.0.0.1`。设置页显示实际地址和端口。
- 文档页在 iframe 中加载，页内导航通过 `postMessage` 回报给 DSH，切换会话后再回来仍停留在最后浏览的文件。
- 服务在会话被归档或销毁时自动停止；插件卸载时全部停止。
- 不持久化服务实例：重启 DSH 后从「已启动」列表重新开始。

## 限制

- 文档服务本身没有鉴权；默认只绑定回环地址。只有在明确需要局域网访问时才把 `bindHost` 改为 `0.0.0.0`。
- 会话视图的**程序化切换**（右键定位后自动切标签、设置页跳转）需要应用 `deepseek-harness-night-cruising/patches` 中的会话视图选择补丁。补丁未生效时，定位/跳转仍会更新 URL，但需要手动点击顶部「文档服务」标签。
- iframe 中的文档页保留 doc-server 自己的浅色样式，不继承 DSH 深色主题，以保持与原实现的完整一致性。
- 只对文档服务支持的扩展名显示「定位文件」：md/html/pdf/pptx/doc/docx/txt 与常见图片；其它类型不显示该菜单项。
