# dsh-account-mesh 安装与原生模块使用说明

本文对应插件版本 `0.1.0-rc.13`。官方 DSH 和夜间巡航版使用同一个插件包。通过插件市场安装或更新时，用户只需选择 `dsh-account-mesh`，宿主的插件管理器会在当前 profile 中安装插件及其声明的依赖。

## 从插件市场安装和使用

1. 在需要互联的两台设备上分别打开宿主，在插件市场安装或更新 `dsh-account-mesh`。如果宿主提示需要重启，退出并重新启动宿主。
2. 两端登录同一账号，在「设置 → Account mesh」查看对端的连接与信任状态。插件建立 WebRTC 连接时会加载 `node-datachannel`。
3. 在同一设置页查看传输模式。官方 DSH 默认使用 JSONL。夜间巡航版默认允许 JLC 加速，实际启用取决于本机能否加载匹配的原生模块。如果手动打开加速后看到「重启即出发」，重启宿主，再确认面板显示「巡航加速中」。

## 两个原生模块如何到位

| 模块 | 安装方式 | 用途和平台 |
| --- | --- | --- |
| `node-datachannel@0.33.6` | 插件在 `dependencies` 中声明版本，宿主安装插件时由 pnpm 一并解析。该库通过可选依赖提供各平台的预编译包，例如 Apple Silicon 使用 `@node-datachannel/darwin-arm64`。 | 官方 DSH 和夜间巡航版都用它建立 WebRTC 数据通道。此版本沿用上一版的依赖声明。 |
| `native/jlc.node` | 这是预编译的 Node 原生扩展。插件的 `files` 清单包含 `native/`，安装插件包时会同时获得该文件。 | 夜间巡航版用它编解码 JSONL 会话数据。当前仓库随附的是 macOS arm64 构建；其他系统或架构要使用 JLC，需要提供匹配的二进制。 |

因此，市场用户无需在宿主安装目录执行 `npm install`，也无需单独安装 JLC。[插件清单](../../package.json) · [WebRTC 加载实现](../../src/transport.js) · [JLC 平台说明](../../native/README.md)

## 从仓库目录开发

当 profile 通过 `link:` 引用 `plugins/account-mesh` 时，宿主直接加载该目录的代码。首次准备源码目录，或拉取更新后插件依赖清单、锁文件有变化时，从夜间巡航项目根目录执行：

```sh
cd plugins/account-mesh
pnpm install --frozen-lockfile
```

如果已有 `node-datachannel@0.33.6`，从 `rc.10` 更新到 `rc.13` 后直接重启宿主即可。这次新增的 JLC 二进制随仓库更新到位。

## 其他插件如何复用 JLC

`dsh-account-mesh` 的 `exports` 没有公开 `./native/jlc.node`。因此，其他插件通过 `require('dsh-account-mesh/native/jlc.node')` 加载时，Node 会拒绝这个包子路径。使用绝对路径在技术上可行，但调用方会依赖本机的 profile 布局、插件安装位置和内部目录结构。

如果多个插件都要使用 JLC，可以把它发布为独立包 `@dsh/jlc`，提供稳定的 `encode`、`decode` 接口和对应平台的二进制，由各插件声明依赖。当前版本已经支持这种加载方式：在没有显式指定模块路径时，加载器依次尝试 `@dsh/jlc`、`native/jlc-<平台>-<架构>.node` 和 `native/jlc.node`。[JLC 加载实现](../../src/codec.js)
