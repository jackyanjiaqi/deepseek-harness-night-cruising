# 子账号与手机信任终端

手机端不作为Agent 而是作为 webrtc+udp lan+tailscale p2p网络的信任节点+消费节点。
当前已测试手机端可以加入 tailscale，手机5g+tailscale将成为其终端特征。

1. 作为通知和授权中心，所有DSH桌面终端的强通知都走手机终端，对比默认接受安全模型更高。
2. 主界面就是底部栏的移动端布局版本，可以远程管理多端的底部栏全局配置，且可以一键同步多端配置以及一键更换主题。
3. 主账号共享受信体系，子账号提权受信体系
    通过检测到手机号与主账号一致从而共同受信，当 a机,b机,phone 在同一个主账号(带手机号)网域内 a->b 发送消息 同时 phone 也会收到,phone点确定(被视为b的动作) b机自动接受。
    主账号下挂 c, d 两个子账号(只有登陆口令，只能由主账号修改和设置其口令) 
    c1机,c2机,phone 在同一个c子账号下登陆,此时a机,b机在主账号登陆
    同处于 a主账号的域中, b子账号登陆手机(有口令就可以登陆)，检测到手机号属于其主账号的，则将b的权限等级视为a主账号，此时 b子账号登陆的dsh受信登记全部提升，a-> 

## 完善的信任体系

能联通是网络层面+软件层面的事，联通之后让通信是权限层面的事。
手机端加入之后受信体系更加完备：

1. 其中第一次连接默认受信，后面可以撤销信任。

2. 以及第一次连接不受信任，需要强通知受信才能继续通信。

## 远程 Agent 终端

因为受信程度更高(手机不容易被破解和软件调试)

- 连接远程dsh主机后，可以全编辑发送消息，驱动远程办公。

> 对比其他dsh主机远程后，只能发送固定文本，比如 "继续", "总结到文档", "排查问题",或字数受到远端主机控制。

- 可以发送文件，结合编辑消息，可以完成更复杂任务。

## 消费终端

是文档服务和网页服务(电台+小游戏)的终端入口

## 批量账号管理

可同时登陆多个主账号

每个主账号下可登陆多个子账号

如果多个账号之间并不在一个局域网内，可以通过切换 tailscale 账号 交叉受信

> 注意交叉受信必须让登陆手机作为 密钥保险柜
