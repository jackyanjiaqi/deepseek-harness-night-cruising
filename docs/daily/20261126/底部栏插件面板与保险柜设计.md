# 底部栏插件面板与“保险柜”设计

> 目标：底部栏从“超时设置专属入口”扩展为插件共用面板基座；原“临时坐舱”改名为**保险柜**。  
> 保险柜不是用户文件暂存区，而是**远端数据在本机的加密临时缓存**：本机不提供查看/下载入口，关闭 DSH 后自动清除，异常退出留下的密文在下次启动清除。

## 1. 定位纠正

原“临时坐舱”设计成“插件写文件、用户浏览/删除”，与真实意图不符。现改为：

| 项 | 旧“临时坐舱” | 新“保险柜” |
| --- | --- | --- |
| 内容 | 插件暂存文件 | 远端会话/JLC archive 的本地缓存 |
| 本机查看 | 文件列表 | **不提供** |
| 删除 | 用户手动删文件 | 用户只能“清空保险柜” |
| 生命周期 | 一直保留 | 正常关闭 DSH 清除；崩溃残留密文在下次启动清除 |
| 磁盘格式 | 明文 | **AES-256-GCM 自有格式**，无明文文件名/内容 |

## 2. 安全模型

- 每个 Host 进程启动时生成随机 256-bit 密钥，**只存在内存**，不写入 profile、不写日志、不下发 Client；
- 每个缓存条目单独随机 nonce，AES-256-GCM 加密，AAD 含 magic/version；
- 磁盘文件：`$DSH_HOME/account-mesh/vault/<sha256(logical-key)>.ncv`，权限 `0600`，目录 `0700`；
- 文件头只有 `NCV1` + version + nonce + GCM tag，无 session id/标题/路径；
- 解密只发生在 Host 内部 transfer 管线；**没有列目录/读取/下载路由**，面板只返回 `{bytes, entries, maxBytes}`；
- 正常 `Mesh.stop` 清空并 `clearSync`；`process.once('exit')` 同步清理；启动时先清空 vault 目录中的陈旧密文；
- 崩溃后密钥随进程丢失，残留 `.ncv` 无法解密；下次启动删除。

**诚实边界**：同一 OS 用户仍可能读取进程内存、ptrace/调试 Host，或从已解锁的 DSH 进程直接调用内部接口；本机制防的是“磁盘上直接看到/拷走远端会话”和“面板/文件管理器浏览”，不是对抗同用户恶意程序或管理员。

## 3. 数据格式

```text
offset  size  field
0       4     "NCV1"
4       1     version = 1
5       12    nonce
17      16    GCM tag
33      ...   ciphertext
```

- 逻辑 key（如 `jlc\0<peer>\0<session>\0<dialog>`）只存在内存；文件名是 SHA-256 摘要；
- 每个 archive 一个文件；不做追加写，更新时写临时文件后原子 rename；
- 超过 `vaultMaxBytes` 按 LRU 淘汰；单条大于上限不缓存；
- 默认上限 256 MiB；不参与模型请求/用量/预算门控。

## 4. 与 JLC 的关系

- `mesh_session_fetch` / `/api/fetch` 完整拉取后，把 JLC archive 写入保险柜；
- 同一进程内再次拉同一 peer/session/priority，先读保险柜并直接 decode，网络块传输跳过；
- 关闭 DSH 后保险柜清空，下次冷启动重新拉取；
- 保险柜只缓存 archive，不改变“接收端不把会话写进 workspace/普通文件”的原则。

## 5. 底部栏 / 面板 API

保留 `NightBar` 注册面（`registerPanel`/`fields`/`get`/`set`），但保险柜不注册“文件桶”：

```ts
interface VaultStatus {
  bytes: number
  entries: number
  maxBytes: number
}

interface NightBarPanel {
  id: string
  title: string
  order?: number
  kind?: 'form' | 'vault-status'
  fields?: readonly NightBarField[]
}
```

- 保险柜面板只显示：`已加密 X MB · N 项`、`关闭 DSH 后清除`、`清空保险柜`；
- 不显示 key、会话名、文件路径、文件列表；
- `clear` 调 Host `POST /account-mesh/api/vault/clear`（或 NightBar 同名动作）；
- 插件可注册普通 `form` 面板；保险柜状态由 Host 提供，不由插件伪造。

## 6. 当前实现状态

- `plugins/account-mesh/src/vault.js`：加密、LRU、启动清理、退出清理、聚合状态；
- `src/transfer.js`：JLC archive 写保险柜、二次拉取命中；
- `src/routes.js`：`POST /api/vault/clear`；
- `client.js`：设置页“保险柜”卡片，仅聚合状态与清空按钮；
- 底部栏静态壳层尚未接入 `NightBar`，因此“保险柜”目前显示在 account-mesh 设置页；底栏入口是下一步。
