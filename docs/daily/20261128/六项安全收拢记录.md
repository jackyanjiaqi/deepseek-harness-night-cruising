# 六项安全收拢记录（dsh-account-mesh）

- 日期：2026-11-29
- 版本：`dsh-account-mesh@0.1.0-rc.17`（未提交、未发布）
- 范围：P0 六项，目标是让插件装到**陌生用户机器**上时，不依赖用户的 FileVault、备份习惯或手工 chmod，也能保持安全默认。
- 前提：本机用户可信；远端（受信 peer）**不可**读到本机密钥与插件私有数据。这次改动就是把这条前提从"默认配置恰好成立"变成"代码保证"。

## 关键语义

### 1. `$DSH_HOME` 是硬拒绝目录

`allowedRoots()` 的来源是 `allowRoots` + 全部 workspace + 全部 session cwd。只要用户把 workspace 设在 `~`，`~/.dsh/account-mesh` 就会落在允许根里。现在 `resolveReadable` 在拿到 `realpath` 后先查拒绝根：

```js
if (this.isDenied(resolved)) throw rpcError('path-denied', ...)
```

拒绝根 = `$DSH_HOME`（或 `DSH_HOME` 环境变量）+ 插件实际 `dataDir`。这意味着：

- `files/read ~/.dsh/account-mesh/identity.json` → `path-denied`；
- `files/list ~/.dsh` → `path-denied`；
- workspace 内指向 `~/.dsh/account-mesh` 的符号链接 → 解析后仍被拒，且不会出现在目录列表里；
- 正常 workspace 文件读取不受影响。

### 2. 自动信任默认关闭

`autoTrustSameAccount` 之前默认 `true`，出厂 bundle 也显式写成 `true`，所以只改代码默认值不够。现在两处都改为 `false`。

语义要写清：开启后，同账号首次接触会排队一条待确认请求（仍需用户在阻塞对话框中选择），但**已信任设备换钥会自动重绑**——`accountTag` 是自报的，局域网可被冒充，所以默认关闭。关闭时同账号设备只做发现，配对必须显式。

### 3. MCP 没有 token 就不启动

之前 `authorized()` 是 `if (!token) return true`，一旦配置了 `mcpPort`，本机任何进程都能调用只读文件面。现在：

- `mcpToken` 为空 → `registerMcp()` 记 error 并返回空 disposer，端口根本不监听；
- `authorized()` 在无 token 时也返回 `false`（纵深防御，防止未来有人绕过启动检查）；
- 默认仍只绑 `127.0.0.1`。

### 4. 权限自愈

`hardenPermissions()` 在每次插件启动时执行，不需要用户操作：

- 目录：数据根、`hosted-vault/`、`vault/` → 0700；
- 文件：`identity.json`、`peers.json`、`settings.json`、`mesh.log`、`hosted-vault/{root.key,ledger.json,host-settings.json,index.json}`、`vault/index.json`、`vault/*.ncv` → 0600；
- 只处理普通文件（`lstat`），跳过符号链接；失败只记 warn，不阻塞启动。

旧版本留下的 `settings.json` 0644 会在下一次启动时自动修好。

### 5. 日志

- 脱敏：`/Users/<name>` → `~`；`192.168.x.x`、`100.x.x.x` → `x.x.x.x`；`127.0.0.1` 保留；`Bearer xxx`、`token=xxx`、`secret=xxx` → `<redacted>`。
- 轮转：超过 5 MB 时 `mesh.log` → `mesh.log.1`（旧的 `.1` 删除），每 200 次写入检查一次，启动时也检查一次。
- 限频：发现层对同一 `address:port` 的发送失败最多每 60 秒记一条，并附带被抑制次数；这解决了之前 4 MB 日志里 7,940 条 `EHOSTDOWN` 刷屏的问题。

## 升级影响

- 显式配置 `autoTrustSameAccount: true` 的用户不受影响；只有依赖默认值的人会从"自动排队"变成"手动配对"。
- 配置了 `mcpPort` 但 `mcpToken` 为空的用户：升级后 MCP 端点不会启动，日志会有一条 error；补一个随机 token 即可。
- 历史 0644 文件在下次启动自动修复；不需要用户操作。
- 现有 `mesh.log` 超过 5 MB 时会在下一次启动被轮转（当前 4 MB，暂不触发）。

## 未覆盖 / 残留

- 本机 root、同用户恶意进程、带 Full Disk Access 的其它应用：插件防不住，也不承诺。
- FileVault/BitLocker、Time Machine 备份：插件只提示，不替用户开启；README 需要补一段威胁模型（本次未改）。
- `identity.json` 私钥与 `hosted-vault/root.key` 仍是 0600 明文（SSH 级基线）；系统钥匙串包裹属于 P1。
- `ledger.json` / `host-settings.json` 的路径、会话 ID 仍是明文元数据（0600）。
- `resolveReadable` 的检查与打开之间仍有 TOCTOU 窗口（符号链接替换），未消除。
- README/README.zh 中"托管保险柜尚未实现"的旧描述仍与 rc.16 代码不一致，属于既有文档债，本次未改。
- 本次改动未提交、未发版；发布前仍需 commit、`npm pack` tarball 验证、干净 profile 安装、30 秒存活与 401 检查。

- 代码：`git checkout -- plugins/account-mesh` 会连同工作区里既有的未提交改动一起回滚，不建议；按文件回退上面列出的 P0 文件即可。
