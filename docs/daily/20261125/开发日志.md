## 2026-11-25 · 进度展示的统一规划（预研结论，本期不实现）

进度展示已在 [jsonl-native-compress](../../../../jsonl-native-compress/) 统一规划。要点：

- **进度来源**：JLC1 块头固定 4B 明文 `progress_code`（块序号 + 千分比，`cumulative_records * 1000 / total_records`），接收端读到块头即可发进度事件，无需解压；`inspect` 可读全部进度。语义是“传输进度”而非“原始 seq 进度”，与用户感知一致。
- **协议**：`HELLO → MANIFEST（文件头+块索引+total_records）→ REQUEST bitmap → BLOCK → ACK bitmap → DONE`；MANIFEST 先行让接收端在收块前就拿到总量——这正是「已拉取 / 总量」对比的正确数据源；断点续传走 `.jlc.part` + bitmap，无超时约束。
- **嵌入形态**：首选 napi-rs 原生模块（`@dsh/jlc`），account-mesh Host 进程内 `require` 调用，`Buffer` 直进 CPU 压缩；MCP 作兜底/外部工具；WASM 仅渲染进程预览。原生模块缺失或版本不符时回退现有 `sessions/events` JSON 分页，插件不因缺模块而失败。
- **对 account-mesh 的落点**（二期实现时）：
  1. `transport.js` 增加 `mesh-bin` 二进制数据通道（可靠有序，`arraybuffer`，64 KiB 分片头 `{transferId, blockId, index, total}`，按 `bufferedAmount` 做背压），控制面仍走 `mesh-rpc` JSON；
  2. 新增只读 op：`sessions/export/manifest` / `sessions/export/block` / `sessions/export/ack` / `sessions/export/cancel`（发送端内存态 transferId，不写远端）；
  3. 接收端写 `$DSH_HOME/account-mesh/incoming/<transferId>.jlc.part`（稀疏写 + CRC 校验 + bitmap），P0（对话优先）到齐即可先渲染对话；
  4. 面板进度 = 已 ACK 块的 permille 聚合 / MANIFEST 总量；本日实现的 `sessionTotals`、缓存、强制刷新与版本互通均为该方案的前置件，`sessions/index` 是 MANIFEST 缺席时的 JSON 降级路径。
