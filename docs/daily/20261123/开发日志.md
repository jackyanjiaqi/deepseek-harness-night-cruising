## 2026-11-23 · P1–P3 实现

文件：

- `index.js`：bundle Host 入口（`apply`），启动 Mesh、注册工具与面板路由。
- `src/account.js`：经 `deepseekAccount.getPlatformSession()` / `getDeviceIdentity()` 读账号与设备标识；**token 只读不落盘、不写日志、不出网**。
- `src/identity.js`：每 home 一套 Ed25519 设备密钥（`$DSH_HOME/account-mesh/identity.json` 0600），`accountTag`、指纹、六位配对码、签名/验签。
- `src/trust.js`：`peers.json` 原子写信任表（0600）。
- `src/discovery.js`：UDP 组播 `239.255.42.99` + 广播；**Tailscale 单播探测**（`os.networkInterfaces()` 的 `100.64.0.0/10` 地址 + `tailscale status --json` 在线设备 + `staticPeers`）。
- `src/signaling.js`：p2play-js 风格房间、字典序小者发 offer、带 Ed25519 签名的 700 字节分片 `offer/answer/ice`。
- `src/transport.js`：`node-datachannel` 双通道（`mesh-rpc` 可靠 / `mesh-ping` 不可靠）、分片重组、状态机。
- `src/mesh.js`：发现→信令→通道→nonce 双向认证→只读 RPC；重连退避；面板快照。
- `src/data.js`：`sessionQuery` 会话投影（不含 reasoning、图片占位）、`workspaceRegistry` 工作区、文件按行读取；`realpath` + 根目录包含校验。
- `src/tools.js`：8 个 agent 工具。
- `src/routes.js`：`/account-mesh/api/state|pair|forget|reconnect`，经 `connection.requestRejection` 鉴权。
- `client.js`：`settings.section` 面板（状态、设备指纹、发现地址、Tailscale、对端信任/重连）。
- `cordis.patch.yml`、`locale/en.json`、`locale/zh.json`、`icon.svg`、`docs/DETAIL.md`。

这一步抓到两个**真实环境才会暴露的 bug**：

1. **服务挂载顺序**：`apply()` 执行时 `tools`、`webServer`、`deepseekAccount` 还没挂载，一次性 `ctx.get()` 拿到 `undefined`，工具/面板路由/发现都起不来。

## 2026-11-23 · 崩溃复盘与修复（第一次重启后）

重启后 Host 退出，崩溃日志：

```
dsh fatal uncaught exception: TypeError: Cannot read properties of undefined (reading 'catch')
    at Timeout._onTimeout (.../plugins/account-mesh/src/discovery.js:119:62)
```

根因：`src/discovery.js` 里 20 秒定时器把**同步方法** `probeStatic()` 当成 Promise 链了 `.catch`，第一次触发就抛 TypeError；DSH 把未捕获异常视为致命错误，宿主直接退出。

修复与加固：

- 删掉错误的 `.catch`；新增 `Discovery.every()/guard()`，所有周期任务（announce / prune / tailnet 探测 / 静态探测）统一 try/catch + Promise rejection 兜底；
- 入站 UDP 数据报处理包在 `guard` 里（`onMessage → handleMessage`），单个畸形包不再能抛到事件循环；
- `Mesh` 的账号刷新 / housekeeping 定时器同样走 `guard`；`acceptOffer` 的 Promise 加 `.catch`；
- 回归：`IDLE_MS=33000` 的双实例 harness 跨过 5s/15s/20s/30s 全部定时器仍 ALL PASS；另起真实 Host 连续运行 50s 未退出（之前 20s 必崩）。

## 2026-11-23 · 按 patches/ 约定做兼容

读了 `patches/deepseek-harness/0.2.2-rc.5/` 的 series 与主要补丁（`002-disable-operation-timeouts`、`004-runtime-limits`、`003-night-cruising`）：本发行版系统性移除应用层超时（模型请求、HTTP、子进程、锁等待、账号授权等只保留用户取消/服务端时间），`004-runtime-limits` 把仍必须传时长的接口统一取 `2147483647`。

据此调整插件：

| 位置 | 原实现 | 现实现 |
| --- | --- | --- |
| `STALE_AFTER`（25s 无流量断链） | 定时器判定空闲即 teardown | **删除**；链路只由 WebRTC 状态、认证失败、用户撤销结束，空闲不中止任何在途调用 |
| 发现层 20s 存在性过期 | 过期同时 teardown 链路 | 只从「在线列表」移除，已建立的数据通道保持，恢复后无需重新握手 |
| `tailscale status` | `execFile({timeout:5000})` | **去掉命令超时**；单飞（single-flight）避免慢 CLI 堆叠进程 |
| 重连 | 指数退避最长 30s | 保留：这是重试节奏，不是中止期限；无次数上限 |
| 账号 profile 读取 | 每 60s 最多一次 | 保留：读取节流，不中止请求 |
| 工具分页 `limit/offset` | 有上界 | 保留：与内置 `read` 语义一致的取数参数，非静默截断 |

`docs/DETAIL.md` 与 `README.md` 增补「与本仓去除超时设计的关系」一节。

## 双实例联调准备

方案 A（推荐，覆盖 Tailscale）：另一台已登录同一账号的机器安装同一插件目录（可 `git clone` 本仓库后 `plugin_manager install_bundle`），两台机器各自重启 DSH；`mesh_peers` 应互相可见，`source: tailnet` 表示经 tailnet 单播探测。

方案 B（本机）：用独立 home 启动第二实例并登录同一账号：

```sh
DSH_HOME="$HOME/.dsh-peer" "/Applications/DeepSeek Harness.app/Contents/MacOS/DeepSeek Harness" \
  --profile desktop
```

（第二个 home 需要在界面里重新登录同账号；`DSH_HOME` 不同的实例 deviceId 不同，才会互相识别。）
