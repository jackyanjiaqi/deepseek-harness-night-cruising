## 1. 需求与验收标准

### 1.1 目标

同一 DeepSeek 账号在两个 DSH 实例上同时登录、同时在线时，两个实例的 agent 可以**只读**访问对方：

- 会话内容（标题、时间、消息、工具调用摘要等）
- 工作空间（工作区列表、目录、文本文件）

通信以账号身份标识作为互相识别的前提；握手协议参考 [p2play-js](https://github.com/aguiran/p2play-js)，握手完成后用 WebRTC 数据通道传输数据。

### 1.2 验收标准（可观测、可复现）

| # | 验收点 |
| --- | --- |
| A1 | 两个已登录同一账号的实例同时在线（同一局域网）时，`mesh_peers` 列出对方，显示「同账号 · 在线 · 已配对/待配对」 |
| A2 | 首次连接默认需要一次显式配对（6 位指纹双向核对）；配对后自动重连，无需再次确认 |
| A3 | 本地 agent 能列出远端全部会话（含离线/历史会话），并读取指定会话的消息与工具调用摘要；**不激活远端 agent**、不写入远端会话 |
| A4 | 本地 agent 能列出远端工作区与目录、按 `offset/limit` 读取远端文本文件 |
| A5 | 服务端强制只读：不存在写操作、prompt 注入、bash、任意命令通道；越界路径、未配对设备一律拒绝并返回明确错误码 |
| A6 | 远端会话/文件读取不经过模型转发，不产生额外 token 消耗；读取结果不静默截断（分页） |
| A7 | 断线自动重连；关闭插件、退出账号、关闭 DSH 后通道立即关闭且不可再访问 |
| A8 | 插件在 Plugins 列表中显示中英文标题/描述/详情/图标；开发日志写入 `docs/daily/20261123/` |

## 2. 调研结论（已核实部分）

| 事实 | 依据 |
| --- | --- |
| 有 `sessionQuery` 服务：`listSessions` / `readSession` / `readSurface` / `readTitleSnapshots`，可读 **live 或已持久化**会话，且不激活 agent | `cordis_inspect_query` → host `Service`，`sessionQuery` 契约 |
| 有 `fs` 服务：`resolve`、`stat`、`readText`、`readByteRange`、`listDir`、`contains`；`workspaceRegistry.list()` 返回工作区 | host `Service` 目录 |
| 账号身份可读：`deepseekAccount.getPlatformSession()` → `{ origin, token, userId }`（Host-only）；`getDeviceIdentity()` → `{ deviceId, userId, osVersion }` | host `deepseekAccount` 契约 |
| 会话落盘形如 `$DSH_HOME/sessions/<工作区 slug>/<sessionId>/session.v4.jsonl.zstd` + `session.lock`；**不应自己解 zstd**，走 `sessionQuery` | 实测 `~/.dsh/sessions/` 目录结构 |
| 已装包里有 LiveShare 体系（`dsh-experimental-liveshare` + `-protocol` + `dsh-api-gateway` + `dsh-api-remote-access`）：Peer principal / 方法级 ACL / Relay 转发，但需要**外部部署的 Relay 服务器 + OAuth**，默认不启用 | 已读三份 README |
| p2play-js（`@p2play-js/p2p-game`）是**浏览器库**：WS 房间信令 → roster → 按 id 字典序确定发起方（小→大）→ `desc`/`ice` 定向转发 → 双数据通道；可选 room JWT 与 `ENFORCE_SESSION_IDENTITY`。它本身**不提供账号身份**，且依赖浏览器 `RTCPeerConnection` | 已读官方 README |
| Host 进程是 Node 24（Electron run-as-node，N-API 10），**没有**原生 `RTCPeerConnection` | 运行时 `process.versions` |
| `node-datachannel@0.33.6` 以平台预编译包提供 N-API 数据通道（`@node-datachannel/darwin-arm64` 等），主包无 install 构建脚本 | npm registry 元数据实测 |
| 插件形态：bundle = `package.json` 的 `dsh.bundle.patch` + `cordis.patch.yml` + `apply(ctx, config)`；工具经 `ctx.tools.register`；配置经 `configEditor`，密钥/凭据经 `ctx.credentials` | `dsh-doc` 的 host-plugin/configuration 参考 |

### 2.1 由此得出的两个关键判断

1. **不复用 LiveShare**：它要求用户另外部署 Relay 服务器并完成 OAuth，与「同账号、无服务器、自动发现」的目标相反；且它共享的是「被授权进入的会话页面」，不是给自己 agent 用的只读数据接口。它的 Peer/ACL 思路留作二期参考。
2. **不直接依赖 p2play-js**：浏览器库在 Host 进程不可用。我们**实现等价的握手规则**（房间 = 账号标签 + 设备对、字典序决定发起方、`desc`/`ice` 定向转发、双通道），把信令从「WS 房间服务器」换成「局域网 UDP 直连」，这样无需任何外部服务即可完成 WebRTC 握手。

### 2.2 尚未核实（P0 阶段验证）

- `node-datachannel` 在 Desktop 的 Host 进程（Electron run-as-node）里能否正常 `require` 并建立数据通道；
- 同一账号在两台设备/两个 `DSH_HOME` 上的 `deepseekAccount` token 是否相同（决定能否做「token 派生 PSK 自动认证」，还是必须走一次性配对）；
- 局域网 UDP 组播/广播在目标网络（macOS 防火墙、公司 AP）是否可用。

│         ▲                 ▲                    ▲             │workspaceReg.│  │

└──────────────────────────────────────────────────────────────────────────────┘
                                  ▲  ▲
                       发现/信令  │  │  只读 RPC（无写、无 prompt、无 bash）
                                  ▼  ▼
┌──────────────────────────── DSH 实例 B（读取方） ────────────────────────────┐
│  account-mesh Host 插件                                                       │
│  同一套发现/信令/通道 + 「远端客户端」+ agent 工具                             │

- 每个实例**同时是服务端和客户端**（对等）。
- 服务端只按白名单响应只读 RPC，**不暴露 DSH 的 Gateway / Remote 命名空间**，避免把整套管理权限暴露出去。
- 数据面读取只调用 DSH 已有的只读服务，不解析会话文件、不激活 agent、不改动会话日志。

## 4. 身份与安全模型

### 4.1 身份

| 概念 | 来源 | 用途 |
| --- | --- | --- |
| `userId`（账号 ID） | `deepseekAccount.getPlatformSession().userId`，缺失时退回 `getDeviceIdentity().userId` | 判定「同账号」候选；无 userId 时插件保持 idle 并提示需登录 |
| `deviceId` | `getDeviceIdentity().deviceId` | 本机身份；用于排序决定发起方、防止自连 |
| `accountTag` | `SHA-256("dsh-mesh/v1:" + userId)` | 只用于发现报文里标识「同账号」，**不泄露 userId、不作为授权依据** |
| 设备密钥对 | 首次运行时本机生成 Ed25519，存 `$DSH_HOME/account-mesh/identity.json`（0600） | 应用层双向挑战认证、配对指纹 |

### 4.2 授权：同账号自动信任 + 一次密钥绑定（已按审核结论调整）

1. 发现到 `accountTag` 相同、`deviceId` 不同的设备 → 尝试建立通道。
2. 首次连接交换公钥，**同账号自动信任**（`autoTrustSameAccount: true`，已确认的默认值），把对端公钥写入信任库 `$DSH_HOME/account-mesh/peers.json`（原子写、0600）。
3. 每次连接都用 Ed25519 挑战应答校验设备私钥，DTLS 证书指纹固定（pin）；公钥变化视为新设备并重新绑定。
4. 面板与工具始终显示设备短码、公钥指纹与首次绑定时间，便于人工核对；可随时 `mesh_peer_forget` 撤销。
5. 需要更严格时可把 `autoTrustSameAccount` 关掉，改为面板里手动配对（同一套指纹）。

> 说明：`accountTag` 只能证明「对方自称同账号」。自动信任意味着局域网/tailnet 内可以冒充同账号，这是审核时明确接受的风险；记录在插件详情页的限制里，并把开关留给用户。

### 4.3 服务端只读约束（硬性）

- RPC op 白名单，物理上不存在写操作（不是权限判断，而是没有对应代码路径）。
- 不提供任何「把文本送进远端会话」的能力：无 prompt、无 bash、无 shell、无 plugin_manager、无 schedule。
- 路径约束：入参路径先经 `fs.resolve`，再用 `fs.contains` 判断是否落在允许根内（工作区目录 ∪ 远端会话 `cwd`）；`realpath` 之后校验；越界返回 `path-outside`。
- 大小约束：文件与事件按 `offset/limit` 分页返回 `hasMore/nextOffset`，**不静默截断**（与 `read` 工具语义一致）。
- 不在线上传输 `token`、`userId` 原文；日志脱敏；不记录对端文件内容。
- 不设置模型请求超时、不设置请求数/用量配额（遵循仓库规则）；只响应用户主动断开/关闭。

## 5. 通信协议

### 5.1 发现（局域网 UDP + Tailscale 单播）

- 默认端口 `47831`（可配置），同时加入组播组 `239.255.42.99` 并向广播地址发送；收到 `query` 立即单播回应。
- 报文（v1，JSON，≤ 1200 字节）：

```json
{ "v": 1, "t": "announce", "tag": "<accountTag 前16字节 base64url>",
  "dev": "<deviceId>", "name": "<peerName>", "sigPort": 47832,
  "pk": "<Ed25519 公钥>", "fp": "<证书指纹>", "ver": "1.0.0" }
```

- 只对 `tag` 相同的设备展示详细信息；其他 tag 只记录「有其他账号设备在线」计数，不建连。
- **Tailscale 组网**：组播/广播不跨 tailnet，因此增加单播探测通道——
  - 本机存在 `100.64.0.0/10` 地址（`os.networkInterfaces()`）时启用；
  - 通过 `tailscale status --json` 列出同一 tailnet 的在线设备，逐个向 `<100.x 地址>:<discoveryPort>` 发送 `query`；对端单播回应 `announce`；
  - 找不到 `tailscale` CLI 时退回 `staticPeers`（支持 `host:port` 与 MagicDNS 名称）；
  - 套接字绑定 `0.0.0.0`，tailnet 与物理网卡共用同一端口；announce 里带 `addrs`，回包走 `rinfo.address`，因此两网段可以互通。
- WebRTC 的 host candidate 会包含 `100.x` 地址，tailnet 内可直接 P2P；不依赖 STUN/TURN。
- 手动对端：Config 里 `staticPeers: ["host:port"]` 作为组播被拦时的兜底（也用于本机双实例测试）。

### 5.2 信令（沿用 p2play 的规则，UDP 直连）

| 规则 | 取值 |
| --- | --- |
| 房间 | `room = base64url(SHA-256(accountTag + 排序后的 deviceId 对))` |
| 发起方 | `deviceId` 字典序**小**者发 offer（同 p2play：小 id → 大 id） |
| 帧 | `{t:"offer"|"answer"|"ice", room, sdp?, cand?, from, mac}`，`mac = HMAC-SHA256(对端公钥派生密钥, 关键字段)` |
| 分片 | SDP > 1200 字节时按 `frag:{i,n}` 分片，收齐后重组；30s 内未收齐丢弃重试 |
| 重试 | offer 未应答则指数退避重发（1s→2s→4s→…，无次数上限；仅用户关闭停止） |

### 5.3 数据通道

- `node-datachannel` 建两条通道：
  - `mesh-rpc`：可靠、有序（JSON 帧）
  - `mesh-ping`：不可靠（延迟/存活探测）
- 帧格式：

```
→ { "id": 12, "op": "sessions/list", "params": { "limit": 50 } }
← { "id": 12, "ok": true, "result": { ... } }
← { "id": 12, "ok": false, "err": { "code": "not-paired", "message": "..." } }
```

- 单帧上限 256 KiB；更大的结果由服务端分页（`result.hasMore` / `nextOffset`），客户端循环翻页或按需继续。

### 5.4 RPC 操作白名单（v1）

| op | 参数 | 返回 | 数据源 |
| --- | --- | --- | --- |
| `hello` | `{ver, name, pk, fp}` | `{ver, dev, name, paired, caps}` | 插件自身 |
| `sessions/list` | `{limit, offset, workspace?}` | 会话摘要数组 `{id,title,cwd,createdAt,updatedAt,live,persisted}` | `sessionQuery.listSessions` + `readTitleSnapshots` |
| `sessions/events` | `{sessionId, fromSeq, limit}` | `{session:{id,title,cwd}, items:[{seq,time,role,text,toolCalls}], hasMore, nextOffset}` | `sessionQuery.readSession`（按 seq 窗口） |
| `sessions/search`（二期） | `{query, limit, cursor?}` | 命中列表 | `sessionQuery.searchSessions` |
| `workspaces/list` | `{}` | `{id,path,title}[]` | `workspaceRegistry.list` |
| `files/list` | `{path}` | `{path, entries:[{name,type,size,mtime}]}` | `fs.listDir` |
| `files/stat` | `{path}` | `{type,size,mtime}` | `fs.stat` |
| `files/read` | `{path, offset, limit}` | `{text, offset, lines, totalLines, hasMore}` | `fs.readLineRange`（UTF-8 按行） |

错误码：`not-paired`、`path-outside`、`not-found`、`unsupported-version`、`bad-request`、`internal`。

### 5.5 连接状态机

`idle → discovering → signaling → connecting → pairing? → ready → （断线）→ signaling … → closed`

- 状态与最近错误可在 `mesh_status` / （二期）面板查看；
- 关闭插件、退出账号、DSH 退出 → 立刻拒绝新连接、关闭数据通道、清空内存密钥（磁盘密钥保留）。

## 6. 数据面细节

### 6.1 会话投影（服务端）

- `sessions/events` 只投影**可读文本**：`user/message`、`assistant/message` 的 `text` 块、`tool/call`（名称 + 参数摘要）、`tool/result`（是否错误 + 首行摘要）。
- 不含 `reasoning` 原文（避免把思考过程整段外泄，二期可配置）；图片以 `[图片: <类型> <宽×高>]` 占位。
- 以 `seq` 为游标分页，避免一次拉完超大会话。
- 通过 `sessionQuery.readSession` 读取，**不激活 agent、不产生模型请求**。

### 6.2 本地 agent 工具

| 工具 | 参数 | 说明 |
| --- | --- | --- |
| `mesh_status` | — | 本机账号/设备、在线对端、配对状态、插件版本 |
| `mesh_peers` | — | 在线与历史对端列表（名称、deviceId 短码、同账号、在线、已配对、延迟） |
| `mesh_session_list` | `peer, limit?, offset?, workspace?` | 远端会话列表 |
| `mesh_session_read` | `peer, sessionId, fromSeq?, limit?` | 远端会话消息窗口 |
| `mesh_workspace_list` | `peer, path?` | 远端工作区/目录 |
| `mesh_file_read` | `peer, path, offset?, limit?` | 按行读取远端文本文件 |
| `mesh_peer_pair` | `peer, code` | 完成一次配对（指纹一致才写入信任库） |
| `mesh_peer_forget` | `peer` | 撤销信任并断开 |

工具都声明 `additionalProperties: false`、`peer` 支持 `deviceId` 或 `peerName`；返回 JSON 文本，错误码原样透出以便 agent 判断。

## 7. 插件工程结构

```
plugins/account-mesh/
├── package.json            # dsh.bundle.patch、exports（./locale/*.json、./icon）、files
├── cordis.patch.yml        # insert: id=account-mesh, name=@local/account-mesh, config
├── index.js                # Host 入口：apply(ctx, config)
├── src/
│   ├── identity.js         # 账号/设备身份、Ed25519 密钥、accountTag
│   ├── discovery.js        # UDP 组播/广播 announce+query
│   ├── signaling.js        # offer/answer/ice、分片、MAC、房间
│   ├── transport.js        # node-datachannel 通道封装、状态机、重连
│   ├── pairing.js          # 指纹、挑战应答、信任库读写（原子写）
│   ├── rpc-server.js       # op 白名单、路径约束、会话/文件投影
│   ├── rpc-client.js       # 远端调用封装、翻页
│   ├── tools.js            # ctx.tools.register 的 8 个工具
│   └── log.js              # 结构化日志（脱敏）
├── client.js               # 二期：Client 面板（状态/对端/配对按钮）
├── locale/en.json          # meta.title / meta.description / meta.detail
├── locale/zh.json
├── icon.svg                # 原创图标
└── docs/DETAIL.md          # 插件详情页：能力、用法、限制
```

Config schema（`Config` 导出，安装后可在 Settings 改）：

```js
{
  enabled: true,                 // 运行开关
  peerName: '',                  // 显示名，空则用 hostname
  discoveryPort: 47831,
  staticPeers: [],               // ["<host>:<port>"]，组播/tailnet 探测不可用时手动指定
  tailscaleProbe: true,          // 通过 tailscale status 单播探测 tailnet 内设备
  autoTrustSameAccount: true,    // 已确认：同账号自动信任（可在面板/配置里关闭）
  allowRoots: [],                // 额外允许读取的根目录（默认只用工作区/会话 cwd）
  stunServers: [],               // 二期跨网用
  signalingUrl: ''               // 二期跨网用（自建 p2play 风格 WS 信令）
}
```

持久化：
- 信任库 → `$DSH_HOME/account-mesh/peers.json`（原子写、0600）
- 设备密钥 → `$DSH_HOME/account-mesh/identity.json`（0600）
- **不**把密钥写进 profile 配置；配置里只放非敏感项。

## 9. 验证方案

### 9.1 环境

- 方案一（推荐）：两台同局域网机器，各自登录**同一账号**；
- 方案二：本机两个独立 `DSH_HOME`（`DSH_HOME_A` / `DSH_HOME_B`），各自登录同一账号后同时启动（同一 `DSH_HOME` 两个实例是「同一设备」，无法验证）。

### 9.2 用例

| 编号 | 用例 | 预期 |
| --- | --- | --- |
| U1 | A/B 同时在线 | `mesh_peers` 互相可见，标记同账号/在线/待配对 |
| U2 | 首次配对 | 两边指纹一致；确认后重连变为 ready |

## 10. 风险与待决

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| R1 `node-datachannel` 在 Electron run-as-node 下加载失败 | 拿不到 WebRTC 通道 | P0 先验证；备选 `werift`（纯 JS WebRTC，体积大、无原生编译） |
| R2 账号 token 是否跨设备一致未知 | 无法做 token 派生 PSK 自动认证 | P0 验证；默认按「一次配对」设计，token 只作附加因子 |
| R3 UDP 组播被防火墙/AP 拦截 | 物理网段发现失败 | Tailscale 单播探测 + `staticPeers` 兜底 |
| R3b Tailscale ACL 拒绝 UDP 或 CLI 不可用 | tailnet 内发现失败 | 探测失败只降级该通道并在面板显示原因；`staticPeers` 兜底 |
| R4 双实例测试需要独立 `DSH_HOME` 与二次登录 | 验收成本 | 在 P2 前准备好测试目录与登录流程 |
| R5 路径 TOCTOU（检查与打开之间换符号链接） | 理论越界读 | 与 DSH 现有实现同等对待（realpath + contains），在 DETAIL 中如实声明 |
| R6 跨网需求是否在本期 | 影响工期 | 默认 P5 可选，按需确认 |
| R7 安装插件会作用于 desktop 所有会话 | 影响面 | 实现完成后单独确认再安装 |
